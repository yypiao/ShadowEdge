# ADR 0001：UI 用 Electron，业务浏览器用打补丁的 Chromium

- 状态：已接受
- 日期：2026-09-08

## 背景

需要一个跨平台桌面客户端来管理数百个隔离浏览器环境，同时业务浏览器必须做到内核级反检测。

## 备选方案

1. **纯自研 Chromium 壳**（紫鸟路线）—— 反检测最彻底，但 UI 迭代成本极高，跨平台适配工作量大。
2. **纯 Electron + JS 注入指纹** —— 开发最快，但指纹易被识破（见 `ANTI_DETECTION.md` §1），Worker 场景无法覆盖。
3. **Electron 做 UI + 独立的补丁 Chromium 做业务浏览器**（选定）。

## 决策

采用方案 3。UI 层与业务浏览器进程完全隔离，通过 CDP 通信。

## 理由

- UI 迭代速度与反检测强度解耦，两条线可并行推进。
- Electron 版本升级不影响业务环境指纹稳定性 —— 这点很关键，用户的环境指纹一旦漂移就可能触发平台风控。
- 团队可用 Web 技能栈开发管理界面，而把稀缺的 C++ 人力集中投入补丁。

## 代价

- 需要分发额外的 Chromium 二进制，安装包体积显著增大（约 +150MB）。
- 需要维护 Chromium 补丁的 rebase 流水线。
- 两套进程模型增加了调试复杂度。
