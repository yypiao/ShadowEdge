# ADR 0002：指纹用种子确定性生成，而非随机生成后持久化

- 状态：已接受
- 日期：2026-09-08

## 背景

每个环境需要一个稳定唯一的指纹。常规做法是随机生成一次然后完整存库。

## 决策

只持久化 `seed`，全部指纹维度由 `seed` 经 `SeededRandom` 确定性推导。

## 理由

- **存储极小** —— 一个环境的指纹从数 KB JSON 降到一个字符串，数万环境的同步成本大幅下降。
- **可审计** —— `auditFingerprint()` 能重新推导并比对，检测出被手工篡改或数据损坏的环境。
- **可迁移** —— 换设备只需同步 seed，不必传输完整画像。

## 代价

**素材库不可重排。** `rng.pick()` 依赖数组索引，一旦在 `DEFAULT_DB` 中间插入元素或重排，所有历史环境的指纹会集体漂移，导致用户账号大面积触发风控。因此：

- 新素材只能追加到数组末尾。
- 素材库结构变更必须走版本化（`dbVersion`），老环境继续用老版本推导。

这条约束已写入 `AGENTS.md` 铁律。
