# 安全基线与威胁模型

## 1. 威胁模型

| 攻击者 | 能力 | 我们的防御 |
| --- | --- | --- |
| 恶意操作员 | 有客户端登录态，想窃取店铺账号密码另开店 | 密码由主进程解密并直接注入页面，明文不经过渲染层与剪贴板；`operator` 角色无 `profile:export-cookie` |
| 离职员工 | 曾持有客户端与部分凭据 | 撤销成员后其 KEK 分片失效，无法解封环境数据；审计链留存全部历史操作 |
| 服务端管理员 / 云厂商 | 可读数据库全部内容 | 环境数据端到端加密，服务端只存密文与被 KEK 包裹的 DEK，无解密能力 |
| 网络中间人 | 可观测流量 | TLS + 证书固定；环境数据在传输前已加密 |
| 恶意网页 | 在业务浏览器内执行 JS | 业务 Chromium 与 Electron 进程完全隔离；渲染层 CSP 禁止内联脚本与外部资源 |
| 供应链攻击 | 污染 npm 依赖 | 依赖锁定 + `pnpm audit` 纳入 CI；主进程依赖保持最小化 |

## 2. Electron 安全基线

全部为强制项，CI 应校验：

```ts
webPreferences: {
  sandbox: true,           // 渲染进程 OS 级沙箱
  contextIsolation: true,  // preload 与页面隔离
  nodeIntegration: false,  // 渲染层无 Node
  webSecurity: true,       // 不禁用同源策略
}
```

- `setWindowOpenHandler` 一律 `deny`，外链交系统浏览器。
- CSP：`default-src 'self'; script-src 'self'`，不允许 `unsafe-eval`。
- preload 只暴露 `IPC_CHANNELS` 白名单，不暴露 `ipcRenderer` 本体。
- 不加载任何远程 URL 到应用窗口。

## 3. 密钥层级

```
用户口令
  └─ PBKDF2 ─→ 用户密钥
        └─ 解封 ─→ 组织 KEK（服务端存被用户密钥包裹的副本）
              └─ 包裹 ─→ 每个环境的 DEK
                    └─ AES-256-GCM ─→ Cookie / Storage 密文

本机 macOS Keychain
  └─ 本地随机 KEK
        └─ 包裹 ─→ 独立 DEK
              └─ AES-256-GCM ─→ 代理密码 / 账密 / Cookie / Storage 快照 / RPA 定时输入
```

- DEK 一环境一密钥，泄露不横向扩散。
- AAD 绑定用途（`KeyPurpose`），防止密文被跨用途重放。
- 密钥轮换：换 KEK 只需重新包裹 DEK，不必重加密全部数据。
- macOS 的本地 KEK 由 Keychain 保管，旧 `vault.key` 只有在 Keychain 写入并读回校验成功后才删除；Keychain 不可用时停止解锁，不静默降级为明文文件。其他平台当前仍使用 0600 文件，Windows DPAPI / Linux Secret Service 属于后续平台工作。
- Keychain 主要防止数据库与密钥文件被一起离线复制后直接解密，不宣称抵御已取得当前用户会话权限或 root 权限的攻击者。

## 4. 敏感数据处理

- 日志与审计写入前经 `redact()`，屏蔽 `password` / `cookie` / `token` 等键。
- 账号密码使用 `account-secret` 用途标签做信封加密，数据库只保存密文、被包裹的 DEK 与 IV；相同用途标签之外不能解封。
- RPA 定时输入使用独立的 `rpa-schedule-input` 用途信封加密；列表 IPC 不回传输入值，仅调度执行时在主进程解封。录制器跳过密码字段，普通文本会在用户确认后作为工作流内容保存。
- 不提供密码 reveal IPC。密码仅在主进程的自动填充调用期间解密，返回给渲染进程的结果不包含用户名或密码，审计同样不记录这两项。
- 自动填充只接受精确的协议 + 主机 + 端口匹配；业务站点强制 HTTPS，HTTP 仅允许本机回环地址。origin 不允许路径、查询参数、片段或用户信息，校验错误不得回显原始输入。
- 填充用户名和密码之前必须确认密码选择器指向 `type=password`；填充过程中再次检查页面 origin，默认只填充，只有显式 `submit: true` 才点击登录。
- 代理密码在内存中的存活时间最小化，用完即置零。
- 崩溃报告不上传 `userDataDir` 内容。
- `.sebackup` 环境备份包含画像、完整代理链凭据、Cookie、LocalStorage 与 IndexedDB，明文只短暂存在于主进程；使用独立口令经 PBKDF2-SHA256（210000 次）派生 KEK，再以 AES-256-GCM 信封加密。口令不写入备份或数据库，保存对话框明确提示其敏感范围。
- 导出要求源环境正在运行，以读取当前浏览器状态；错误口令、认证标签不符或密文篡改都会拒绝导入。导入始终生成新环境及代理 ID，不覆盖既有环境。
- Cookie、LocalStorage 与 IndexedDB 快照在 SQLite 中使用本机 KEK 的 `profile-cookie` 用途加密。正常关闭先捕获状态，成功写库后才删除 Chromium 数据目录；下次启动通过闸门后恢复。快照会保留为崩溃恢复基线，不再于首次恢复后删除。
- 当前备份不包含 SessionStorage、账号凭据库、RPA 工作流、定时配置/输入或运行历史，也不等同于自动云同步；OPFS 已纳入加密快照与备份。备份文件与口令必须分开保管；获得两者即可还原其中全部站点状态与代理凭据。

浏览器运行期间仍需要 Chromium 数据目录。正常关闭、批量停止和应用退出统一经过加密快照与目录清理；若快照捕获或写库失败，则保留目录并明确报错。异常退出可能留下 Chromium 已落盘数据，下次启动优先从该目录恢复，避免被旧快照回滚；快照仅补回目录缺失的 Cookie，同名同域路径以目录为准。只有后续正常关闭才重新加密并清理。崩溃时尚未由 Chromium 刷盘的 LocalStorage 等修改无法保证恢复，建议同时启用操作系统全盘加密。

当前账密托管的安全边界是**单客户端本地加密存储与填充**。团队授权、云端零知识同步、设备撤销和服务端 KEK 分片尚未实现，不能把本地链路描述为已经完成团队端到端加密。

## 5. 内核启动授权

- 自研 Chromium 只接受桌面主进程签发的短期启动令牌；每次启动使用独立随机 KEK、DEK、IV 与 nonce。
- 令牌使用 `auth-token` 用途的 AES-256-GCM 信封加密，包含签发时间、过期时间和环境 ID；默认有效期 60 秒（Chromium 0009 协议允许的上限），覆盖 component 内核冷启动。
- 密文令牌通过命令行传递，KEK 仅存在于本次浏览器进程环境且不写磁盘。浏览器进程完成早期校验后立即清除 KEK，避免继续传给后续子进程。
- 无令牌、错误 KEK、认证失败或过期都会拒绝浏览器启动；`--version` 等不创建浏览器会话的查询不受此限制。
- 签名安装内核按环境固定版本，启动前逐版本重新验签与哈希校验；全局切换不能改变历史环境，固定版本缺失或篡改会明确拒启。

该边界用于阻止绕过 launcher 直接运行浏览器会话，并提供短期重放窗口；它不是针对本机 root/逆向攻击者的DRM，也不替代 T17B 的分发包签名与文件完整性校验。

## 6. 审计不可篡改

`AuditEvent.hash = sha256(prevHash || canonicalJson(event))`，形成单向链。服务端每日把链尾哈希提交到外部时间戳服务，使得连管理员也无法在事后重写历史而不被发现。

## 7. 已知残余风险

- 若攻击者获得操作员机器的 root 权限，可 dump 主进程内存拿到解密后的密码。缓解：短生命周期 + 可选硬件密钥（Phase 3+）。
- 平台方若采用行为生物特征（打字节律、鼠标微动）检测，纯指纹伪造不足。缓解见 `ANTI_DETECTION.md` §4。
- Chromium 补丁需跟随上游版本维护，滞后期间存在已知 CVE 暴露窗口。缓解：补丁最小化 + 自动化 rebase 流水线。
